MOEIFY / INFERNEON — RESEARCH EVIDENCE FACT SHEET
Snapshot: 2026-11-13, updated 2026-11-22. Outcome-level disclosure; implementation withheld.

Research direction
Investigate whether capable language-model inference can run on inexpensive, locally controlled hardware. Moeify is the model-research track; InferNEON (execLLM) is bare-metal firmware with no operating system, running on an 8 GB Raspberry Pi Compute Module 4 (quad Cortex-A72, 1.5 GHz) and a 2017 Lenovo ThinkCentre M710q office PC (Core i3-7100T); the Lambda Engine builds a model's inference engine from its published files. This is ongoing research.

Measured on the CM4
• CM4 component timings: Median 3.8060 ms (1 thread), 1.0323 ms (4 threads). Sources S041, S044. Linux microbenchmark. Mean 3.8141 → 2.0322 ms; p99 worsens 3.9165 → 10.1716 ms. Not token latency.
• Physical Ethernet: 70,000 exact UDP echoes in 12.12 s. Sources S05. User-supplied transcript; mixed payloads; no packet capture or post-run CRC count; not model throughput.
• Physical CM4 generated response: HTTP 200 with generated Hi; 13 prompt tokens and 1 completion token in all four recorded requests. Sources S11A, S11B. One board; one greeting prompt. Establishes endpoint execution, not general answer quality or interactive latency.
• Physical CM4 repeated-request latency: 565.37 s → 269.08 s; 2.10x faster; 52.41% lower latency. Sources S11A, S11B. Compare the second request of each session. First requests took 565.01 s and 560.97 s. One observation per condition; no uncertainty estimate or steady-state tokens/s claim.
• 27B streamed answer on the CM4: 32 tokens; first token 82.24 s for a 24-token prompt; 3.814 s/token mean over 31 intervals; 200.46 s total. Sources S12. One prompt, one run, temperature 0. Not a quality evaluation.
• 27B later build on the CM4: 3.584 s/token mean over 42 intervals (range 3.571–3.594); first token 82.4 s for a 42-token prompt; cold first request 367.9 s to first token. Sources S13. Different prompts from C12, so not a matched before/after comparison. Cold time includes loading model data from SD.
• Gemma 3 1B on the CM4: 0.36 s/token over 39 steps; first token 6.1 s for a 20-token prompt; output begins with the exact 32-token Hugging Face fp32 greedy text; follow-up turn 0.31 s/token reusing 26 of 40 prompt tokens. Sources S14, S17. Two prompts on one board. 8-bit weights. Third-party model; not a quality benchmark.
• Gemma 3n E4B on the CM4: 1.66 s/token with drafting off (min 1.65, max 1.66); with 1B drafting 1.95 s/token (40 of 55 drafts accepted) — slower; the 59-token answer is identical to the host 8-bit reference and begins with the 16-token Hugging Face fp32 greedy text. Sources S15, S17. One prompt. The drafting-off first-token time reused cached prompt tokens and is not a cold prompt time.
• NVMe boot on the CM4: 8.60 GB copied once from SD to NVMe in 477 s; NVMe load 57 MB/s with checksum verification; afterwards 1.65 s/token, first token 32.7 s for a 20-token prompt. Sources S16. Load rate sampled over 10 s, not a full timed boot. One drive. Generation speed is unchanged by the drive.
• LFM3-1.7B on the CM4: 0.584 s/token on three fixed prompts (32 greedy tokens each), first token 8.5–10.5 s for 21–22 prompt tokens; with the Lambda Engine's generated engine the same three texts and prompt token counts at 0.578 s/token. Sources S17, S21. Three prompts, one board, temperature 0. LFM3 is licensed for non-commercial use only.
• The 27B model on llama.cpp vs the bare-metal firmware, same board: On the same Raspberry Pi CM4: the third-party 27B ternary base model on llama.cpp under Linux decodes at 4.386 s/token and reads the prompt at 3.521 s/token; Attis on the bare-metal firmware decodes at 3.5432 s/token (1.24x faster) and read a 42-token prompt in 82.4 s (1.96 s/token, 1.80x faster). Sources S22, S13. Not a matched experiment: measured on different dates with different builds and run lengths (32 generated tokens on llama.cpp); Attis adds post-trained components to the base model, so it does more work per token, not less.

Measured on the ThinkCentre
• Attis 27B on a 2017 office PC: Lenovo ThinkCentre M710q (2-core i3-7100T), booted from a USB stick with no operating system: 0.848 s/token (first port, 15 Nov) → 0.787 → 0.521 s/token (compiled engine, parameters chosen by the board's own sweep) → 0.344 s/token with dual-channel memory; the same text on the three fixed prompts at every step; first token 5.77 s. Sources S18. One machine. Builds and the memory configuration changed between steps; no step is a controlled experiment. Attis is adapted from a third-party base model.
• Long prompt on the ThinkCentre: A 3076-token prompt: the same text from the reference and the compiled engine; with attention heads on all four cores 972 s against 1189 s. Sources S18. One prompt, one run each.
• Own drivers on the ThinkCentre: The firmware's own network driver: 1.55 µs per frame sent against 36.7 µs through the UEFI driver. Integrated GPU (Intel HD 630): a first command executed under the firmware, its written value read back. Sources S18. The GPU result is first light only; no model computation runs on the GPU.
• LFM3-1.7B on the ThinkCentre, generated engine: The Lambda Engine's engine generated from LFM3's config.json, its tokenizer and chat template read from the model's own files: 0.111 s/token, first token 1.8–2.2 s; the same texts as the CM4 on the three fixed prompts (first run with a scalar kernel: 1.47 s/token). Sources S21. Three prompts, one machine, temperature 0. 8-bit weights. LFM3 is licensed for non-commercial use only.

Measured on two boards
• One model on two machines: ThinkCentre + CM4 serving Attis together with the layers split between them: the same text as one board, 0.906 s/token. Row parallel (both boards compute every matrix, rows split by measured speed): logits identical to one machine bit for bit; link round trip 137 µs median. Sources S19. Demonstrates correctness of the split, not a speed-up: two boards were slower than the ThinkCentre alone on this link.
• Same container, two architectures, same answers: One LFM3 container serves on the CM4 (ARM) and the ThinkCentre (x86) with the generated engine: the three 32-token answers are identical on both machines and identical to the hand-written board engine. Sources S21. Three prompts. Identical text, not a quality evaluation.

Measured off-board (laptop or evaluation computer)
• 27B quality: 10.8204 → 9.6052 perplexity; 11.23% reduction. Sources S01. Recorded same-series evaluation; limited WikiText slice. Not broad accuracy or statistical significance.
• Deployment candidate: 9.6245 perplexity; 0.201% above selected research checkpoint. Sources S01, S02. Selected point from five distinct recorded evaluations; no independent holdout confirmation.
• Component numerical agreement: 64 checks; worst maximum absolute difference 2.416e-13. Sources S03. FP64 component comparisons on test inputs; not full-model equivalence or hardware precision.
• Host execution: One full 64-layer forward; finite output scores; 59.597 s. Sources S07. Laptop scalar test. Next token after opening chat marker was user; answer quality not demonstrated.
• Host regression checks: 35 passed, 0 failed, 2 ignored; 512 tokenizer fixture comparisons within one test. Sources S08. Historical host suite, not 512 separate test functions; newer physical endpoint evidence is in S11A and S11B.
• Artifact footprint: 7,359,800,072 bytes / 7.3598 GB. Sources S10. File size only; excludes runtime state and memory requirements.
• Port conformance (off-board): Gemma 3 1B tokenizer 2,916/2,916 texts identical; LFM3-1.7B reference vs the publisher's code: next token equal at 498/498 positions; LFM3 tokenizer 825/825; LFM3 8-bit image 32/32 greedy tokens equal; chat prompts 12/12. Sources S17. Laptop only. Agreement with reference implementations, not answer quality.
• LFM3 web-search decisions (off-board): 15/20 correct with a client-side rule vs 8/20 with the tool always offered, on 20 prompts unseen while designing the rule. Sources S17. Small set, full-precision model on the laptop. The 8-bit board model may decide borderline prompts differently.
• The Lambda Engine against reference implementations: 20 published checkpoints on their real weights matched to Hugging Face transformers (f32) in every layer within 1e-4 relative with the same next token at every position; 48 architecture families on small random models built from published configurations within 5e-5; SmolVLA against LeRobot; engines generated from config.json identical to the hand-written board engines in 49,829,376 values; tokenizers identical on 3 families; 21 published chat templates rendered identically to transformers on 584 renders. Sources S20. Laptop only. Agreement with reference implementations, not answer quality. Families on small random models are checked for architecture, not for their real weights.

Secondary record
• Earlier 1.7B track: 17.6496 → 17.6809 perplexity; failed run recorded at 244.1. Sources S09. Secondary project notes; no raw evaluation trace bundled; not compared with 27B results.

What remains to prove
Independent evaluation of answer quality on a fresh benchmark set; repeated sessions with uncertainty estimates; energy, temperature and long-run reliability; a speed-up from using two boards together (correctness is shown, speed is not); model computation on the integrated GPU; and the practical cost and energy case. Speeds of different models are not a speedup of one model, and no build-to-build cause is isolated with matched controls.
